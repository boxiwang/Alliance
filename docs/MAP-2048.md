# Map 2048 — plan (owner decisions 2026-09-28)

Kingshot comparison: at a zoom where every resource is readable, crossing its map takes
~2.5 minutes of dragging; ours (512×512, ~90 tiles per screen at Tactical) takes ~30 s.
Holding 1,024 players is not the same as giving 1,024 players room: alliances need their
own territory with plenty of resource points. So the State grows.

## Decisions

| Topic | Decision |
| --- | --- |
| Size | **2048 × 2048** (×4 per side, playable circle ≈ 3.2M tiles, 16× today) |
| Opening | **By quadrant** at public launch: new players spawn in the active quadrant; when its population reaches a threshold, new spawns move to the next quadrant. Unopened quadrants hold no targets until they open. |
| March speed | Raised overall: **outer edge → centre ≈ 30 minutes** (today ~25 min for a quarter of the new distance). |
| Resources | Engineer's call, constraint: **no lag, low device requirements**. Area-based density inside opened quadrants: ~1 resource planet per 100 tiles and 1 Rogue per 400 tiles (≈ 8k + 2k per quadrant; a readable screen shows ~a dozen targets). The client only renders its view; Strategic zoom uses server-side clusters. |
| Zoom | Anchored to pixels per tile (not "whole map fits"), so a readable screen shows ~45 tiles across. |
| Migration | City coordinates ×4 (relative layout kept), targets regenerated, fleets recalled home first. |

## Why the engine must change first

Benchmark (laptop, 10,725 entities, 64 players, state 3.3 MB): one dispatch **104 ms**
(repeated whole-world `structuredClone`s), one alarm advance 23 ms, one full save 10 ms
of serialization + a 3.3 MB write. Cloudflare's free tier allows only a few ms of CPU per
request, so the shared world needs:

1. **In-place mutation** in the shared world (no whole-world copies). A D1 conflict
   (rare) discards the in-memory world and reloads the last committed copy from storage.
2. **Spatial index** for nearby queries (view, search, spacing checks).
3. **Chunked, dirty-only persistence** (entities by sector; players, marches, events and
   reports separately).

Target after the refactor: a dispatch in a few ms; a save writes only changed chunks.
Then measure on Cloudflare; if the free tier still is not enough, the owner decides on
Workers Paid ($5/month).

## Phases

1. Engine performance (above) + benchmark.
2. 2048 config: world size, zones, Wormhole reserve, outer-ring spawns per quadrant,
   quadrant opening rule, area-based ecology, march speed, zoom model, view cap.
3. Migration of the live shared world (coords ×4, regenerate targets, settle fleets).
4. Then P0-5 PvP on the new distances.

## Open

- Quadrant opening threshold (players per quadrant before the next one opens).
- Whether unopened quadrants are enterable (no targets yet) or sealed.
